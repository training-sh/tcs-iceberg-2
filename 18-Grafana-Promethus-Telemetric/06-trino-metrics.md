# Trino metrics in Prometheus

Open **Observe → Metrics** in the OpenShift Administrator console. Paste one expression at a time and select **Run queries**. Use **Last 30 minutes** for graphs. A metric key is its Prometheus name. Labels such as `pod`, `container`, and `component` identify the series under that key. In the inventory queries, each result label `__name__` is a metric key and the numeric value counts matching series.

## Available keys by source

Snapshot verified against the lab on 20 November 2026. The exporter reads the Trino coordinator and republishes the key families below. The exporter label `pod` identifies its scrape target. Use native OpenShift metrics and their workload `pod` labels to compare process resource usage across coordinator and workers.

| Source | Available keys |
| --- | --- |
| Exporter health | `bigdata_service_up{component="trino"}` |
| Trino coordinator exporter | 192 keys under QueryManager, ClusterMemoryManager and GcMonitor |
| Coordinator pod | 48 native pod, container and recording-rule keys in the snapshot |
| Worker pods | The worker StatefulSet had zero replicas. Live worker queries returned no series, and the six-hour inventory also returned no keys. The current exporter reads the coordinator endpoint. |

## List the keys and labels in the UI

List every currently available coordinator application key in the three exported families.

```promql
count by (__name__) ({namespace="bigdata",job="bigdata-metrics",__name__=~"trino_execution_name_QueryManager_.*|trino_memory_name_ClusterMemoryManager_.*|io_airlift_stats_name_GcMonitor_.*"})
```

List Trino pods and containers with current working-set memory samples.

```promql
count by (pod, container) (container_memory_working_set_bytes{namespace="bigdata",pod=~"trino-.*",container!="",container!="POD"})
```

List current native keys for the coordinator and workers, respectively.

```promql
count by (__name__) ({namespace="bigdata",pod=~"trino-[0-9]+"})
```

```promql
count by (__name__) ({namespace="bigdata",pod=~"trino-worker-.*"})
```

To see whether any Trino worker series were collected in the last six hours, run this expression. This reports sample presence even when the worker stopped before the current instant.

```promql
count by (__name__) (present_over_time({namespace="bigdata",pod=~"trino-worker-.*"}[6h]))
```

## Query single metrics

Check whether the exporter reached Trino. A value of 1 confirms endpoint reachability.

```promql
bigdata_service_up{namespace="bigdata",component="trino"}
```

Read the coordinator's cumulative completed-query count.

```promql
trino_execution_name_QueryManager_CompletedQueries{namespace="bigdata"}
```

Read the number of currently running queries.

```promql
trino_execution_name_QueryManager_RunningQueries{namespace="bigdata"}
```

Read Trino's total cluster memory reservation in MiB. This is Trino's engine reservation.

```promql
trino_memory_name_ClusterMemoryManager_ClusterTotalMemoryReservation{namespace="bigdata"} / 1024^2
```

## Aggregate and compare

Add running and queued queries for a snapshot of the query load.

```promql
sum({namespace="bigdata",job="bigdata-metrics",__name__=~"trino_execution_name_QueryManager_(Running|Queued)Queries"})
```

Compare aggregate CPU per coordinator or worker pod, in cores averaged over five minutes. Only pods with samples appear.

```promql
sum by (pod) (rate(container_cpu_usage_seconds_total{namespace="bigdata",pod=~"trino-[0-9]+|trino-worker-.*",container!="",container!="POD"}[5m]))
```

Count ready Trino worker pods. The fallback displays zero when no ready worker series match.

```promql
count(kube_pod_status_ready{namespace="bigdata",pod=~"trino-worker-.*",condition="true"} == 1) or vector(0)
```

Inspect working-set memory in MiB per worker container. This query executed successfully and returned no samples while the worker had zero replicas.

```promql
container_memory_working_set_bytes{namespace="bigdata",pod=~"trino-worker-.*",container!="",container!="POD"} / 1024^2
```

All examples and inventory queries were checked as instant and range requests against the lab Prometheus query backend.
